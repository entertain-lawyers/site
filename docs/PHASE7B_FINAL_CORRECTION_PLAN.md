## POST -> RESOURCE TRANSACTION DESIGN

For the 11 SHOULD_BE_RESOURCE records, the exact atomic sequence is:
1. `prisma.resource.upsert({ where: { id: deterministicId }, create: {...}, update: {...} })`
2. `prisma.redirect.updateMany({ where: { destination: '/news/' + oldPostId }, data: { destination: '/resources/' + deterministicId } })`
3. `prisma.post.delete({ where: { id: oldPostId } })`

**Safety guarantees**:
- The transaction is atomic (`prisma.$transaction([...])`).
- Redirect SEO value is preserved.
- If rerun, the upsert is idempotent and the redirect update will simply affect 0 rows. (The delete would throw an error if already deleted, so the script should check `if (existingPost) { delete }`).

## DOCUMENT & B2 PLAN

**B2 Target**: 21 Class C `PutObject` calls to `documents/<sha256>/<filename>`.
**Privacy**: The B2 bucket is inherently private. Public access is forbidden by `src/app/api/media/[...key]/route.ts`. Files will remain private.
**Authorization**: Access requires invoking `getSecureDocumentUrl` which validates JWT auth and active premium entitlement before returning a 300-second presigned URL.
**Neon Document Writes**: 21 `prisma.document.upsert()` creating records containing the `storageKey`, `fileSize`, and `mimeType`.
**Resource Update**: 21 `prisma.resource.update({ where: { id }, data: { documentId: doc.id } })`.
